   prerequisite in Task 0 is satisfied.
3. Before each commit: run the task's verification commands, then

   and stop for release approval; tagging, publishing, and host deployment wait
   for that approval.

## Global constraints

Copied from the approved spec; these are not open for reinterpretation during
implementation.

- **Product:** one self-hosted Docker app, one page after login, one bot per
  directory, one Docker container per bot.
- **v1 scope only:** list bot directories; show live/stopped status, Docker
  health, and uptime; Start; Stop; autostart toggle. No logs, no bot
  creation/editing/renaming/deletion, no migration, no Telegram API calls, no
  restart button, no multiple users.
- **Bot contract:** a bot directory contains a `Dockerfile` or a `bot.toml`
  (or both, with `image` and Dockerfile mutually exclusive); optional
  `bot.toml`, `.env`, `.dockerignore`. No Compose per bot, no framework
  detection.
- **Builds:** Dockerfile bots rebuild on every Start, using Docker layer cache.
  Prebuilt images are pulled only when missing.
- **Autostart:** Docker restart policy `always` / `no`; no systemd. Toggling on
  a never-started bot builds/creates without starting it.
- **Data:** named Docker volumes only, prefixed `anqa-<slug>-`; never removed by
  Anqa; bot source is read from a read-only `/bots` mount.
- **Docker access:** direct `/var/run/docker.sock`; documented as
  root-equivalent; no socket proxy or host agent.
- **Auth:** generated first-run token, stored at `/data/token`, mode `0600`;
  `ANQA_TOKEN` overrides; HttpOnly, SameSite=Strict cookie; optional Bearer.
- **Runtime identity:** dashboard runs as host UID/GID with the Docker socket
  GID via `group_add`; no root dashboard process.
- **UI identity:** terminal-inspired; JetBrains Mono; Light/Dark/OLED; Telegram
  blue default and Rust orange alternative; responsive; accessible; no
  gradients, glassmorphism, shadows, emoji, or decorative art.
- **Naming:** project/repo `Anqa`; crate/binary/image `anqa`; image
  `ghcr.io/benyamin-git/anqa`; containers `anqa-<slug>`; images
  `anqa/<slug>:latest`; volumes `anqa-<slug>-<name>`.
- **Deployment:** port `7409`; host stack `/srv/stacks/anqa`; dashboard registry
  entry `anqa: 7409`; `compose.yaml` for the published image and
  `compose.dev.yaml` for local builds.
- **Platform:** Linux container only; multi-arch `linux/amd64` and
  `linux/arm64`; no native Windows/macOS artifacts.
- **Release:** MIT, `v0.1.0`, GHCR, GitHub Actions, real-Docker integration
  tests, manual browser smoke test. No standalone binaries.

## Resolved implementation decisions

These fill gaps in the spec. The spec's core decisions remain unchanged.

| # | Decision | Why |
| --- | --- | --- |
| I1 | **BuildKit** via bollard's `buildkit_providerless` feature, using the Docker API `/session` upgrade over the mounted Unix socket. Builder version 2, a unique session ID per build, tar context body. | BuildKit is Docker's current builder; the session upgrade works from inside the dashboard container, unlike a separate localhost session. Avoids the deprecated legacy builder and avoids shipping a Docker CLI. |
| I2 | The orphan-cleanup sentinel lives at `/data/.anqa-volume` and stores the bots root's Unix `dev:ino`, not a file inside `/bots`. | `/bots` is read-only (A11), so a sentinel cannot be created there. `dev:ino` detects a missing or replaced bots volume; an in-place empty directory keeps the same ID, so deleting all bot directories still triggers cleanup. This is the one intentional deviation from the literal A14 wording; see "Spec amendments". |
| I3 | All lifecycle mutations (Start, Stop, Autostart) return `202 Accepted` and run in the background under a per-bot lock. The UI observes progress and errors through the 2-second poll. | Uniform, avoids HTTP requests lasting minutes for builds, and matches the spec's "long operations return 202". Immediate validation/Docker-unavailable errors still return 4xx/5xx. Build failures after `202` are reported in the card's `error` field. |
| I4 | `GET /api/bots` returns `{"bots":[...]}`. Bot objects keep the spec's fields; `image` and `health` are nullable for error/no-health cases; `uptime_seconds` is `0` when not running. | Explicit envelope and types; no database or state file. |
| I5 | A bot qualifies for listing when it contains `Dockerfile` or `bot.toml`. Invalid manifests are returned as `status: "error"` cards rather than failing the whole response. | Spec A17/A6; one bad bot must not hide the rest. |
| I6 | `autostart` is true only for Docker restart policy `always`. `unless-stopped` and other policies are shown as false and are overwritten by the toggle. | Spec defines autostart as `always`/`no`; Anqa is the source of truth for its own containers. |
| I7 | Start on an already-running bot is an idempotent no-op. The UI disables it; the API does not tear down a running bot. | Avoids an accidental rebuild/restart path; spec says Start is disabled while running. |
| I8 | Config hash = SHA-256 of canonical JSON `{image, command, env, ports, volumes}`. Image ID is compared separately. `.env` values are hashed, never logged or returned. | Recreates on env/manifest changes and on a new image; named volumes preserve data. |
| I9 | `.dockerignore` is evaluated by Anqa while assembling the tar; `.env` (any path), `.git` directories, and `.dockerignore` itself are always excluded; `Dockerfile` is always included. Symlinks are archived as symlinks, not followed. | Respects the contract, prevents secret baking, and keeps context assembly under our control. Docker applies the same ignore file if it is sent, so we omit it. |
| I10 | Dashboard healthcheck (`anqa healthcheck`) opens a TCP connection to `127.0.0.1:${ANQA_PORT}` with a 2-second timeout. `/healthz` remains the HTTP liveness endpoint. | Distroless image has no curl/shell; TCP connect proves the process is listening. |
| I11 | `tower-http` is not used. Security headers, JSON content-type enforcement, and request logging are small custom axum middleware. | Fewer dependencies and a smaller binary; the spec listed tower-http only as "compatibility to be verified". |
| I12 | `GET /api/bots` returns `503` when the bots root is unreadable or Docker is unavailable. If only individual manifests are invalid, it returns `200` with error cards. | Matches A15 while keeping partial failures visible. |
| I13 | Stop uses Docker's 10-second grace period; a stop request on a stopped/missing container is a successful no-op. | A24; idempotent lifecycle calls. |
| I14 | The prebuilt-image pull path splits the image reference into repository/tag, defaulting to `latest`; digest references are passed through. | Docker's `/images/create` treats an untagged `fromImage` as "all tags", which is not wanted. |
| I15 | The published image is pinned in `compose.yaml` as `ghcr.io/benyamin-git/anqa:v0.1.0`; `compose.dev.yaml` is a standalone local dev service with an `anqa:dev` build. | Clear public install path; local development does not require a registry. |

## Spec amendments (approved)

One amendment was required by the spec's own constraints; the rest are
clarifications, not scope changes. All four were approved 2026-11-15.

1. **A14 sentinel location and persistence.** The spec says the app creates a
   `.anqa-volume` sentinel in the bots root, but A11 says the bots root is
   mounted read-only. The sentinel will live at `/data/.anqa-volume` and store
   the bots root's `dev:ino`. Consequently `/data` holds two small files
   (`token` and `.anqa-volume`), not only `token`; there is still no database or
   JSON application state. The first sight of a readable bots root, or a
   changed root fingerprint, writes the sentinel and skips cleanup for that
   startup. The same root with an in-place empty directory does run cleanup.
2. **Async operation errors.** The HTTP API returns `202` for Start/Stop/
   Autostart and reports failures through the bot's `error` field after the
   operation. Immediate errors (unknown bot, invalid manifest, busy, Docker
   down) return 4xx/5xx.
3. **Build backend.** BuildKit (builder version 2) instead of the legacy
   builder. This is an implementation detail within the spec's "bollard"
   decision.
4. **Healthcheck transport.** The subcommand checks TCP liveness, not an HTTP
   GET; the HTTP `/healthz` endpoint remains unchanged.

Approved. A14 was amended in the spec in this commit; `/bots` remains
read-only and `/data` holds `token` and `.anqa-volume`. No other spec
amendments are planned.

**Data flow.** `main` loads config, bootstraps the token, creates the Docker
client, writes/checks the sentinel, attempts orphan cleanup, then serves axum.
`GET /api/bots` scans directories, lists managed containers, inspects each,
merges in-memory operation state, and returns `BotView`s. Mutations acquire a
per-bot lock, return `202`, and run build/lifecycle work in a spawned task.

**Source of truth.** Docker owns container state, restart policies, images,
health, and named volumes. The filesystem owns bot source and manifests. Anqa
keeps only token/sentinel files and in-memory operation errors.

## Interfaces and contracts

### Configuration (`config.rs`)

```rust
pub struct Config {
    pub bind_addr: SocketAddr,      // 0.0.0.0:${ANQA_PORT:-7409}
    pub bots_dir: PathBuf,          // ${ANQA_BOTS_DIR:-/bots}
    pub data_dir: PathBuf,          // ${ANQA_DATA_DIR:-/data}
    pub docker_socket: PathBuf,     // ${ANQA_DOCKER_SOCKET:-/var/run/docker.sock}
    pub token_override: Option<String>, // ${ANQA_TOKEN}; never logged
    pub secure_cookie: bool,        // ${ANQA_SECURE_COOKIE} == "1"/"true"
}

impl Config {
    pub fn from_env() -> anyhow::Result<Self>;
}
```

`ANQA_PORT` is a `u16` from 1–65535; bind address is always `0.0.0.0`.
`ANQA_TOKEN` is used only when non-empty. `Config::from_env` uses a private
`from_map` helper so tests do not mutate process-global env. Debug output must
redact `token_override`.

### Auth (`auth.rs`)

```rust
#[derive(Clone)]
pub struct Auth { /* token, secure_cookie */ }

impl Auth {
    pub fn load(config: &Config) -> anyhow::Result<Self>;
    pub fn new(token: String, secure_cookie: bool) -> Self; // tests
    pub fn verify(&self, candidate: &str) -> bool;
    pub fn set_cookie(&self) -> String;
    pub fn clear_cookie(&self) -> String;
}

pub fn session_from_headers(headers: &HeaderMap) -> Option<String>;
```

Token rules: 32 random bytes, base64url without padding, 43 characters. Load
order: `ANQA_TOKEN`; `/data/token`; generate. Generation creates the file with
`create_new(true)` and mode `0600`, logs the token once at `info`, and handles
an `AlreadyExists` race by reading the winner. Existing empty/whitespace-only
token files are a startup error with a message to delete/rotate. Never log an
existing token.

Constant-time comparison: length check, then `subtle::ConstantTimeEq` on the
byte slices. Cookie is `anqa_session=<token>; HttpOnly; SameSite=Strict;
Path=/; Max-Age=2592000`, plus `; Secure` when configured. Logout uses
`Max-Age=0` and the same flags.

### Bot model and discovery (`bots/`)

```rust
#[derive(Deserialize, Serialize)]
#[serde(deny_unknown_fields)]
pub struct Manifest {
    pub name: Option<String>,
    pub image: Option<String>,
    pub env_file: Option<String>,
    pub command: Option<Vec<String>>,
    #[serde(default)] pub ports: Vec<String>,
    #[serde(default)] pub volumes: Vec<String>,
}

pub enum BotSource { Dockerfile, Image }

pub struct ResolvedBot {
    pub dir: String,
    pub slug: String,
    pub name: String,
    pub image: String,
    pub source: BotSource,
    pub manifest: Manifest,
    pub env: Vec<(String, String)>, // sorted, secrets
    pub ports: Vec<PortSpec>,
    pub volumes: Vec<VolumeSpec>,
    pub config_hash: String,
}

pub struct Discovery {
    pub bots: Vec<ResolvedBot>,
    pub errors: Vec<BotErrorCard>,
}

pub fn scan(root: &Path) -> Result<Discovery, ScanError>;
pub fn load_bot(root: &Path, dir: &str) -> Result<ResolvedBot, BotError>;
```

Manifest rules enforced exactly as the spec's D6/A6: strict unknown-field
rejection; `image` and `Dockerfile` mutually exclusive; explicit `env_file`
must exist; default `.env` is optional; argv command; named-volume-only
`name:path`; `host:container[/tcp|udp]` ports with optional host IP (IPv4,
hostname, or bracketed IPv6); no duplicate ports/targets; absolute container
paths; no `..`; Docker-safe names and length limits.

`slugify(dir)`: lowercase ASCII; keep `[a-z0-9_.-]`; other characters become
`-`; trim leading/trailing `.-_`; reject empty; reject longer than 63 bytes.
Directories whose slugs collide are both surfaced as error cards ("directory
names map to the same Docker slug; rename one").

Discovery scans immediate children only; skips hidden names, non-directories,
and symlinks; a directory qualifies with `Dockerfile` or `bot.toml`; reads at
most 1 MiB of manifest/env; sorts by directory name. A directory with neither
source is ignored. An invalid manifest becomes a `BotErrorCard` without
aborting the scan. `root` unreadable/missing is a `ScanError`, not an empty
list.

Config hash: SHA-256 over `serde_json::to_vec` of:

```json
{"image":"anqa/echo-bot:latest","command":["python","-u","bot.py"],
 "env":[["TELEGRAM_BOT_TOKEN","..."]],"ports":["8080:8080"],
 "volumes":["data:/app/data"]}
```

The hash is hex; environment values are included but never logged.

### Docker status (`docker/status.rs`)

```rust
#[derive(Serialize, Clone, Copy, PartialEq, Eq)]
#[serde(rename_all = "lowercase")]
pub enum BotStatus { Running, Stopped, Starting, Restarting, Unhealthy, Error, Building, Stopping }

pub enum HealthStatus { Healthy, Unhealthy, Starting } // serialized lowercase

pub struct ContainerView {
    pub status: BotStatus,
    pub health: Option<HealthStatus>,
    pub uptime_seconds: u64,
    pub autostart: bool,
}

pub fn from_inspect(inspect: &ContainerInspectResponse) -> ContainerView;
pub fn uptime_seconds(started_at: Option<&str>, now: OffsetDateTime) -> u64;
```

Mapping:

| Docker state | `status` |
| --- | --- |
| `running`, health `healthy`/none | `running` |
| `running`, health `starting` | `starting` |
| `running`, health `unhealthy` | `unhealthy` |
| `restarting` | `restarting` |
| `stopping` / `removing` | `stopping` |
| `created`, `exited`, `paused`, empty | `stopped` |
| `dead` | `error` |
| no container | `stopped` |

`health` is `healthy`, `unhealthy`, or `starting`; Docker `none`/empty becomes
`null`. Uptime parses `State.StartedAt` as RFC 3339; running only; parse failure
logs at debug and yields `0`. `autostart` is true only for restart policy
`always`. Inspect error for one bot yields `status: "error"` with the error
message; it does not fail other cards.

### Docker client (`docker/mod.rs`)

```rust
#[derive(Clone)]
pub struct DockerClient {
    socket: PathBuf,
    inner: Arc<tokio::sync::RwLock<Option<Docker>>>,
}

impl DockerClient {
    pub fn connect(socket: &Path) -> Self; // missing socket => unavailable, not fatal
    pub fn is_available(&self) -> bool;
    pub async fn try_negotiate(self) -> Self; // logs and keeps default on failure
    pub async fn ping(&self) -> Result<(), DockerError>;
    pub async fn list_managed(&self) -> Result<Vec<ContainerSummary>, DockerError>;
    pub async fn inspect(&self, id_or_name: &str) -> Result<Option<ContainerInspectResponse>, DockerError>;
}
```

Connect with `Docker::connect_with_socket(socket, 1800, API_DEFAULT_VERSION)`.
`bollard` returns `SocketNotFoundError` when the socket path is absent;
`DockerClient::connect` logs that and stores `None` so the server still starts
and returns `503`, as required by A15. Every request obtains the client through
a private async helper: if `inner` is `None`, it retries the socket connection
and stores the result on success, so a Docker socket that appears later is
picked up without restarting the dashboard. `ping`/list/inspect return
`DockerError::Unavailable` while the socket is still unavailable. The
1800-second hyper read/write timeout keeps a slow but progressing build from
being cut off before the 30-minute build timeout.

`ping` is used before mutations and by startup checks. `list_managed` uses
`ListContainersOptionsBuilder::default().all(true).filters(&{"label":
["anqa.managed=true"]}).build()`. `inspect` maps HTTP 404 to `Ok(None)`; other
bollard errors become typed `DockerError::{Unavailable, Conflict, Api}`.

### Build context (`docker/context.rs`)

```rust
pub fn build_context(root: &Path) -> Result<Vec<u8>, ContextError>;
```

Blocking; callers use `tokio::task::spawn_blocking`. Walk with `walkdir`
(`follow_links(false)`), sort relative paths, apply:
- `.dockerignore` via `ignore::gitignore::GitignoreBuilder` and
  `matched_path_or_any_parents`;
- hard excludes: files named exactly `.env` (not `.env.example`), any `.git`
  path component, `.dockerignore`;
- force include: `Dockerfile`;
- regular files via `append_path_with_name`, directories via `append_dir`,
  symlinks via a `Symlink` header and `append_link`, other file types skipped
  with a debug log. Set `builder.follow_symlinks(false)` as defense in depth.
- Tar paths are relative and use `/`; empty directories are preserved.

### Image build (`docker/build.rs`)

```rust
pub async fn ensure_image(docker: &DockerClient, bot: &ResolvedBot) -> Result<String, BuildError>;
pub async fn build_dockerfile(docker: &DockerClient, bot: &ResolvedBot) -> Result<String, BuildError>;
pub async fn pull_image(docker: &DockerClient, image: &str) -> Result<String, BuildError>;
```

Dockerfile build:

1. `spawn_blocking(build_context)`.
2. Random session ID `anqa-<slug>-<32 hex chars>`.
3. `BuildImageOptionsBuilder::default().dockerfile("Dockerfile").t(&bot.image)
   .version(BuilderVersion::BuilderBuildKit).session(&session_id).rm(true)
   .labels(&image_labels).build()`.
4. `docker.inner.build_image(options, None, Some(body_full(tar.into())))`.
5. Consume the stream (log `stream`/`status` at debug, truncate to 2 KiB);
   any `Err` becomes `BuildError::Docker`; 30-minute timeout.
6. `inspect_image(&bot.image)` and return `ImageInspect.id`; missing ID is an
   error.

Prebuilt images: `inspect_image`; if 404, `create_image` with parsed
repository/tag, consume to completion, then inspect. Never pull when the image
already exists.

### Lifecycle (`docker/lifecycle.rs`)

```rust
pub async fn start_bot(docker: &DockerClient, bot: &ResolvedBot) -> Result<(), LifecycleError>;
pub async fn stop_bot(docker: &DockerClient, bot: &ResolvedBot) -> Result<(), LifecycleError>;
pub async fn stop_container(docker: &DockerClient, container_name: &str) -> Result<(), LifecycleError>;
pub async fn set_autostart(docker: &DockerClient, bot: &ResolvedBot, enabled: bool) -> Result<(), LifecycleError>;
pub async fn set_restart_policy(docker: &DockerClient, container_name: &str, enabled: bool) -> Result<(), LifecycleError>;
pub async fn ensure_orphan_cleanup(docker: &DockerClient, bots_dir: &Path, data_dir: &Path) -> Result<CleanupReport, CleanupError>;
```

Start: inspect existing container by `anqa-<slug>`; verify the
`anqa.managed=true` label first. If `State.Paused` is true, do not treat it as
running; recreate. Otherwise, if running, no-op. Ensure image (BuildKit or
pull). Ensure named volumes. Inspect existing; if managed label, config hash, and
image ID match **and** the state is reusable (`created`, `exited`, or `running`,
not `dead`, `paused`, or `removing`), reuse; otherwise stop/remove (force, keep
volumes) and create. Preserve `always`/`no` restart policy on recreate. Then
start. A non-managed container with the same name is `NameConflict`; never
remove it. A `dead`/`paused`/`removing` container is recreated rather than
reused so Start cannot silently do nothing.

Container creation:

- `CreateContainerOptionsBuilder::default().name("anqa-<slug>").build()`.
- `ContainerCreateBody`: `image`, `env` (sorted `KEY=VALUE`), `cmd` from
  manifest, `exposed_ports` (`"8080/tcp"`), `labels`
  (`anqa.managed=true`, `anqa.bot=<dir>`, `anqa.config-hash=<hash>`,
  `anqa.version=env!("CARGO_PKG_VERSION")`), `host_config`.
- `HostConfig`: `mounts` (`MountType::VOLUME` for each prefixed volume),
  `port_bindings` (`PortMap`), `restart_policy` (`ALWAYS`/`NO`),
  `log_config` (`json-file`, `max-size=10m`, `max-file=3`), `auto_remove=false`.
- Volumes are created first with `VolumeCreateRequest` and labels
  `anqa.managed=true`, `anqa.bot=<dir>`; creation is idempotent. Anqa never
  removes volumes.
- `start_container` on `created`; 304/already-running is success.
- Stop: inspect; stop only if running/restarting, `StopContainerOptions` `t=10`;
  missing/stopped is success; keep container and volumes. `stop_container` and
  `set_restart_policy` take only the container name so Stop and autostart-off
  still work when the manifest is temporarily invalid. Both verify the
  `anqa.managed=true` label and refuse a non-managed container with a
  `NameConflict`; they never touch user containers that happen to share the
  name.
- Autostart: existing container → `update_container` with the new
  `RestartPolicy`; no container + enabled → ensure image and create without
  starting; no container + disabled → no-op. Never starts a stopped bot.

### Orphan cleanup (`docker/cleanup.rs`)

```rust
pub struct CleanupReport { pub skipped: bool, pub removed: Vec<String>, pub errors: Vec<String> }
```

Sentinel: `/data/.anqa-volume` contains `<dev>:<ino>` from
`std::os::unix::fs::MetadataExt` for the bots root. If missing or different,
write the current value and return `skipped=true`. If the root is unreadable,
skip without updating. If same, list managed containers; for each label
`anqa.bot`:

- invalid label (empty, `/`, `\`, `..`) → remove container;
- root-relative entry missing, a file, or a symlink → remove container;
- a real directory → keep.

Remove with force; never remove volumes. Per-container failures are logged and
collected; cleanup continues. Startup calls this after Docker connect; failure
is logged, not fatal.

### API (`api.rs`)

Routes:

| Method | Path | Auth | Result |
| --- | --- | --- | --- |
| GET | `/` | public | embedded `index.html` |
| GET | `/assets/*path` | public | embedded asset or 404 |
| GET | `/healthz` | public | `200 {"status":"ok","version":"0.1.0"}` |
| POST | `/api/login` | public | `200 {"ok":true}` + cookie / `401` |
| POST | `/api/logout` | auth | `204` + clear cookie |
| GET | `/api/bots` | auth | `200 {"bots":[...]}` / `503` |
| POST | `/api/bots/{dir}/start` | auth | `202 {"ok":true}` |
| POST | `/api/bots/{dir}/stop` | auth | `202 {"ok":true}` |
| PUT | `/api/bots/{dir}/autostart` | auth | `202 {"ok":true}` |

`BotView`:

```json
{
  "dir": "echo-bot",
  "name": "Echo Bot",
  "status": "running",
  "health": "healthy",
  "uptime_seconds": 812,
  "autostart": true,
  "busy": false,
  "error": null,
  "image": "anqa/echo-bot:latest",
  "ports": ["8080:8080"],
  "volumes": ["data:/app/data"]
}
```

`image` is `null` for invalid-manifest cards; `health` is `null` when Docker has
no healthcheck; `status` is `error` for invalid manifests or single-container
inspect failures. `ports`/`volumes` are the validated manifest strings. The full
response is `{"bots":[...]}`.

Error body: `{"error":{"code":"...","message":"..."}}`. Codes:
`unauthorized`, `invalid_token`, `bad_request`, `invalid_manifest`,
`not_found`, `conflict`, `unsupported_media_type`, `docker_unavailable`,
`bots_unavailable`, `internal`. 401 responses include
`WWW-Authenticate: Bearer realm="anqa"`.

Middleware order: security headers outermost; JSON mutation content-type check
on `/api`; auth on protected routes. `POST /api/login` and `/api/logout` require
`Content-Type: application/json`; login has no Docker dependency. Static assets
are public. API responses use `Cache-Control: no-store`; static assets use
`no-cache` (font may use a short public max-age).

Security headers: CSP `default-src 'self'; base-uri 'none'; form-action 'self';
frame-ancestors 'none'; img-src 'self' data:; font-src 'self'; style-src
'self'; script-src 'self'; connect-src 'self'`, plus `X-Content-Type-Options:
nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`,
`Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(),
usb=()`.

### Operation state (`state.rs`)

`AppState` holds `Arc<Config>`, `DockerClient`, `Arc<Auth>`, `Arc<BotOps>`, and
the version string. `BotOps` is a `std::sync::Mutex<HashMap<String, BotOp>>`:
per-bot `Arc<tokio::sync::Mutex<()>>`, `busy: bool`, optional phase, last error.
`begin(dir, phase)` uses `try_lock_owned`; busy → `None`/409. The returned
`OperationGuard` clears busy/phase on drop; `finish(error)` records the last
error, truncated to 2 KiB on a UTF-8 boundary so a chatty build log cannot
balloon the 2-second polling response. All operations spawn a task and return
202; no operation holds an HTTP request open for a build. `GET /api/bots` reads
a snapshot; it never blocks on an operation lock.

## Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| Bollard BuildKit session support fails on Docker 29 | Task 8 spike must pass before lifecycle/UI work; stop and report rather than switching backends silently. |
| Docker group prerequisite missing | Task 0 gate; no Docker runtime verification before it. |
| Socket permissions in the container | Compose `user` + `group_add`; docs show `stat -c '%g'`. |
| `.dockerignore` semantics differ from Docker | Pre-filter with `ignore`; tests for negation, nested paths, `.env`, `.git`; fixture build checks. |
| Build context accidentally includes secrets | Hard-exclude `.env`; never include `.git`; test tar entries. |
| Build/recreate races | Per-bot `try_lock_owned`; 409; 2s polling; no global lock. |
| Orphan cleanup removes live containers | `/data/.anqa-volume` dev:ino sentinel; first-run/changed-root skip; read-only bots root; volumes never removed. |
| Long builds block the UI | 202 + background task + polling; 30-minute timeout; per-bot busy. |
| Token leakage | Log only on generation; mode 0600; no token in API/HTML; constant-time compare; secure cookie option. |
| Docker API changes | Pin bollard 0.21.1; negotiate version; integration tests against Docker 29. |
| Multi-arch build time/failures | Native build per platform in Actions; GHA cache; QEMU; release only on tags. |
| GHCR package stays private | Explicit release-checklist step to make the package public. |
| UI regressions without browser CI | Manual browser smoke; `node --check`; semantic markup; no inline scripts. |
| `read_only` root surprises | Only `/data` is written; no temp files; token/sentinel there; healthcheck TCP only. |
